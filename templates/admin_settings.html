Protection Keeps the platform fast and the AI quota safe
{{ switch_row('enableRateLimits', 'enable_rate_limits', 'bi-speedometer2', 'Rate limiter (friendly request limits)', 'Slows down only scripts and runaway loops. Normal use is never affected. Turn it off for load tests or if a very large group on one network ever sees a "please slow down" message.', settings.enable_rate_limits) }}
What it does and how it works
  • Why it exists. Every interview answer calls the Gemini AI, which has a limited free quota. Without a limit, one script or a stuck page could use it all, or slow the site for everyone.
  • How it works. The platform counts requests in a short sliding window. If a person or script goes far above normal use, the next request shows a calm "You're going a little fast" page that says how many seconds to wait. After that, everything works again. There are no bans and no penalties.
  • The limits are very generous. About 30 interview answers a minute, 600 requests a minute per signed-in candidate, 400 a minute per visitor who is not signed in, 30 resume uploads an hour and 120 practice sessions an hour. A person cannot reach these numbers.
  • Candidates stay safe. A limited request never uses an interview attempt, never loses saved progress, and the interview resumes from the Back button.
  • Fair on shared networks. Signed-in candidates are counted per account, so a whole classroom on one college network does not block each other.
  • Administrators are never limited, and the page itself, images and the interview heartbeat are never counted.
  • When to turn it off. During a load test, when many people sign in at the same moment from one address, or while you are debugging. It is safe to leave on for normal use.
  • If the limiter itself ever has a problem, requests simply go through. It can never take the site down. The server owner can also loosen every limit with the RATE_LIMIT_SCALE environment variable (for example 2 doubles all limits).
