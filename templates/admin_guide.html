Module 02

Assessment Token Quota & Unlock System

To prevent candidate quota spamming while maintaining fair access, the platform incorporates a robust token-governed attempt limit engine.

Phase 1
Default Quota

New candidates are allocated default attempt tokens (default: 2 sessions) configurable in Admin Settings.

Phase 2
Quota Depletion

Each completed, terminated or exited formal assessment consumes 1 token. Platform, AI or connection errors never do: the interview is saved and the candidate continues where they left off. When remaining tokens reach 0, the candidate dashboard locks.

Phase 3
Admin Unlock (+1)

Admin clicks Authorize & Unlock on the candidate row to grant exactly +1 fresh assessment token.

Phase 4
Dynamic Re-Lock

The Unlock button disappears immediately and only reappears once the candidate exhausts their newly granted token.

Smart Token Formula: allowed_total = default_allowed + extra_allowed  |  remaining_tokens = max(0, allowed_total - attempts_used)
Automated Email Dispatch

Upon unlocking a candidate's session, the backend automatically triggers an HTML email notification to the candidate informing them that their studio session has been authorized.

Module 03

Interview Integrity & Strikes

Scored assessments are protected by a set of integrity rules. Everything is counted and stored on the server, so clearing browser data or editing the page cannot reset it. Practice labs are never proctored. You control every rule from Settings → Interview Settings → Integrity & proctoring.

Every violation is a strike

You set the strike limit (1 to 5, default 2). Each violation is one strike. The candidate sees a box for every strike that names the exact mistake, the strike count (for example Strike 1 of 2) and a warning. Their live counter Strikes 1 / 2 stays visible.

Reaching the limit ends the session

The session is recorded as Terminated (Breach) with a 0/10 score and the reason. It counts as one attempt, and the candidate receives a neutral email. A platform or connection error never counts.

Exited early. If the candidate presses Exit, the assessment ends for good. The questions they answered are evaluated by the AI and the candidate sees only that analysis; your admin report also lists each question with their answer. It counts as one attempt and it is never marked as recommended. The candidate receives the "incomplete session" feedback email (switched by the feedback-email setting).

Integrity log (only you see it)

The admin report lists every violation and review flag with the time, question number and exact details, plus the strike total. Candidates never see this log. You can switch it off in settings.

One master switch

At the top of the integrity group, All integrity features turns every option on or off in one click. You can also switch each option yourself; the master then shows a mixed state such as 6 of 8 on.

If a server error happens mid-interview

The interview is saved on the server. The candidate sees a clear page with one Back button, and Back resumes at the next question. No attempt is used. See Module 11.

Module 05

AI Qualitative Scoring & Scorecard Generation

Upon interview conclusion, the Gemini generative model conducts deep multi-turn rubric evaluation across the entire conversational and coding transcript.

Quantitative Score (0 - 10)

Synthesized rating based on technical depth, problem-solving accuracy, clarity, and communication effectiveness.

Written Evaluation Report

Three professional paragraphs: overall performance, a technical critique of the answers, and guidance for improvement. Shown on the scorecard and printable as PDF.

Session Code

Every result has a unique code such as AIS-000042, searchable on the dashboard and quoted in emails and feedback.

Feedback Email

After each result the candidate is emailed their score and three next steps. A failed AI evaluation stores nothing, uses no attempt, and can be retried.

Resume-Aware Questions

The candidate's resume is given to the AI each turn of a formal assessment, so questions can refer to their real projects and skills. Practice modes do not use it.

Data Retention

The raw question-and-answer transcript is kept only while an assessment is in progress. After evaluation only the score, report and metadata are stored.

Module 08

Feedback & Reviews Inbox

Candidates can send a rating and a message from the Feedback item in their dashboard menu, or from the Give Feedback button on every interview report. It arrives in your mailbox, and a copy is saved in the database.

Where it is delivered

To the address in FEEDBACK_TO_EMAIL. If that is not set, the mailbox the platform sends from (MAIL_USERNAME) is used.

Sender details included

Name, email address, account type, course or role, member-since date, sign-in method and user ID. Passwords and tokens are never included.

Feedback details

Topic, star rating, the page it was sent from, the interview session code (from a report), the time, and whether replies are allowed.

Reply directly

When the candidate allows contact, the email's Reply-To is their address, so pressing Reply reaches them. Otherwise the email says contact is not allowed.

Limits & safety

10 to 1000 characters, 5 messages per candidate per hour, logged-in candidates only. All text is HTML-escaped. A mail failure never loses a message.

Module 09

Emails & Sign-in Security

What the platform emails, and how login codes and sign-in attempts are protected.

One-time codes

Stored only as a keyed hash on the server (never in the browser). 5 wrong attempts cancel the code, a new one can be requested after 30 seconds, and at most 5 per hour per email.

Sign-in lockout

5 wrong passwords for the same email and device lock sign-in for 15 minutes. This protects the admin account too. A locked user simply waits, or uses the email-code login.

Verified accounts

Signup requires the emailed code before a password can be set, and an email-code login only creates an account after the code is verified. Reset forms never reveal whether an email exists.

Google sign-in

Always shows Google's account chooser, so users pick which Gmail to use. Your OAuth client needs this site's /auth/google/callback as an authorised redirect URI.

Forged-request protection

Every form and every background request carries a secret per-session token, so another website cannot make your browser delete a user or change settings. If a page sits open for a long time you may be asked to reload it.

Automatic sign-out

An idle admin session ends after 30 minutes, a candidate session after 2 hours, and no session lasts longer than 12 hours. Signed-in pages are never cached by the browser.

Deletes are deliberate

Deleting a record or a user is a confirmed button press (never a plain link), so it cannot be triggered by a stray click or a malicious web page.

Passwords and sign-in messages

New passwords need 8+ characters with a letter and a number, and common or email-based passwords are refused. Wrong sign-ins always show one identical message, so nobody can discover which emails are registered.

Friendly rate limiter

Counts requests in a short sliding window and slows down only scripts and runaway loops, so the AI quota is protected. Limits are very generous (for example about 30 interview answers a minute), signed-in candidates are counted per account, administrators are never limited, and a limited request never uses an attempt. Switch it on or off in Settings → Protection, where the same explanation is shown.

Optional admin two-step sign-in

Set ADMIN_2FA=true and the admin password is followed by a six-digit code emailed to the admin address. Leave it off if your email delivery is not reliable yet.

Module 10

AI Reliability & Configuration Reference

How the AI engine protects live interviews, and every environment variable the platform reads. Only names and purposes are listed here: secret values live in your hosting dashboard (or the local .env file) and are never shown in the app.

Resilient AI calls

Each AI call has a short time limit, automatic retries, and optional backup keys and models. If everything fails, a non-repeating fallback question is used and no attempt is consumed.

Five practice modes

Viva Voce, FluentFlow, Debate with AI, Healthy Convo and Concept Drill each have their own prompts and encouraging evaluation criteria.

Database

Neon PostgreSQL through DATABASE_URL. On Render the app refuses to start without it, so data is never silently written to a temporary file.

Module 11

Preparation Library, Link Health & Error Recovery

What candidates can search and save, how you keep every link working, and what happens if a server error ever interrupts an interview.

Searchable library

Candidates open Search all resources from the Resources page. They can filter by track and format, search by topic, save links with a bookmark, and follow three 7-day study plans. Study-plan ticks stay on their own device.

Link Health (admin only)

Open Links in the top bar, then press Run check now. About 90 links are tested in the background in roughly half a minute. Dates and statuses are shown only here, never to candidates.

Refused is not broken

Some sites turn away automatic visitors (they answer 403 or 429). Those are marked Refused and usually open fine for a person. Only Broken links need action.

Hide a bad link

Press Hide on any link and it disappears from the library and the question pages straight away, with no code change. Press Show to bring it back.

If a server error happens

Candidates see a clear page that says their interview is safe and no attempt was used, with one Back button. Back reopens the saved interview at the next question. The page shows a short reference code (for example ERR-4F2A91); the same code appears in the server log so you can find the cause.
